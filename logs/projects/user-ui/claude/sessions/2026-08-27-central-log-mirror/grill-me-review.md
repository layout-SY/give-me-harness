# Grill Me 검토

- [x] neutral question-first 적용 여부
- [x] 질문이 검토자를 특정 구현 선택으로 유도하지 않는지 여부

## Neutral Question Flow (중립 질문 흐름)

| 영역 | 중립적 질문 | 답변 | 근거 | Recommended Answer (권장 답변) |
| --- | --- | --- | --- | --- |
| 원본 | 중앙 로그와 프로젝트 로그 중 어느 쪽이 활성 세션의 기준인가? | 프로젝트 로그가 원본이고 중앙은 Git 아카이브 사본이다. | 진행 중 파일을 중앙에서 역동기화하지 않는 단방향 계약 | 활성 작업과 이력 보관의 책임을 분리한다. |
| 범위 | 세션 폴더 전체를 복사해야 하는가? | 아니다. 정책이 요구하는 정확한 8개 파일만 필요하다. | transcript·이미지·임시 파일 유입 방지 요구 | 폐쇄형 허용 목록을 유지한다. |
| 삭제 | 프로젝트에서 없어진 산출물을 중앙에서도 지워야 하는가? | 아니다. 별도 Git 이력용 보관 목적과 충돌한다. | 사용자 요청의 프로젝트와 별개 Git 로그 관리 | 중앙 자동 삭제를 하지 않는다. |
| 동시성 | 네 세션이 동시에 종료되면 중앙 파일이 손상되는가? | 각 프로젝트·채널 경로가 분리되고 파일 교체가 원자적이라 부분 파일은 노출되지 않는다. | 프로젝트/채널 경로와 `atomic_write` | 현재 단방향 원자 교체를 유지한다. |
| Git | 종료 훅이 중앙 저장소를 자동 커밋해야 하는가? | 아니다. 사용자 승인 게이트와 병렬 Git 잠금 위험에 어긋난다. | Git 명령 실행 전 사용자 판단 정책 | 복사만 자동화하고 커밋은 수동 승인한다. |
| 배포 | 중앙 로그가 미커밋이면 정책 sync도 막아야 하는가? | 로그만 미커밋인 경우에는 막지 않아야 한다. | 새 세션 종료 때마다 정책 배포가 불필요하게 봉쇄되는 모순 | `logs/**`만 청결 판정에서 제외한다. |
| 실패 | 종료 수집 실패가 세션 완료를 계속 막아야 하는가? | 오류는 보여야 하지만 무한 Stop 반복은 피해야 한다. | Codex Stop의 종료 코드 의미와 수동 재수집 경로 | 수집 오류는 1로 보고하고 다음 종료 시 재시도한다. |

## 결론

- 요구한 별도 Git 로그 관리는 기존 중앙 CLI와 호스트 수명주기에 작은 단방향 수집기를 추가하는 것으로 충족된다.
- 역동기화·자동 삭제·자동 Git 작업을 배제해 네 세션 병렬 운용과 사용자 승인 정책을 유지했다.
- 소비자 정책 sync 전에는 자동 훅이 적용되지 않으므로 최초 수집은 중앙 CLI로 별도 실행해야 한다.
