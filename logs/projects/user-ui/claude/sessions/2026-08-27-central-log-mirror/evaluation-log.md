# 중앙 필수 산출물 로그 미러링 평가 로그

## Watcher 판정과 구분

Watcher는 현재 요구 범위의 구현을 PASS로 판정했다. 아래는 현재 통과 여부를 바꾸지 않는 장기 관찰 사항이다.

## 장기 관찰 사항

- 현재 `logic` 채널은 Codex와 OpenCode가 같은 `.codex/logs/sessions/`를 공유한다. 향후 두 호스트가 동일 프로젝트에서 같은 task slug를 동시에 작성한다면 세션 디렉터리 이름 규약 또는 host 하위 구분을 재검토할 수 있다.
- 중앙 사본은 삭제를 전파하지 않으므로 장기간 누적 용량을 관찰해야 한다. 실제 용량 문제가 측정되기 전에는 보존 정책을 추가하지 않는다.
- 원자 교체는 부분 파일 노출을 막지만 서로 다른 세션이 동일 대상 파일을 동시에 다른 내용으로 쓰면 마지막 완료본이 남는다. 현재 파일 소유권 계약상 같은 산출물의 동시 작성은 허용되지 않는다.

## 재사용 가능 자산

- `collect_project_logs`: 폐쇄형 산출물 목록을 프로젝트·채널별로 증분 보관하는 중앙 수집기.
- `collect-logs` CLI: 자동 훅 실패 시 사용하는 수동 복구 진입점.
- `central_status_entry_is_log_only`: 정책 소스 청결과 운영 데이터 청결을 분리하는 보수적 porcelain 판정.

## 기술 부채

- 소비자 정책이 아직 동기화되지 않아 자동 훅은 활성화되지 않았다.
- 기존 legacy `harness_core.py` 불일치는 중앙 시스템 전환과 별도로 사용자 판단이 필요하다.
- OpenCode adapter는 설치된 1.18.19 V1 계약을 대상으로 하며 V2 업그레이드 시 event와 permission smoke를 함께 갱신해야 한다.

## 프로세스 개선 사항

- 중앙 로그 커밋 주기는 사용자가 여러 세션의 종료분을 묶어 판단하는 방식으로 시작한다.
- 실제 충돌이나 저장 용량 문제가 관찰되면 그 근거를 바탕으로 host 식별자 또는 보존 정책을 추가한다. 현재는 선제 추상화를 도입하지 않는다.
