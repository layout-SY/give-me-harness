# Grill Me 검토

## Method Guardrails (검토 방법 안전장치)

- [x] neutral question-first 적용 여부
- [x] 질문이 검토자를 특정 구현 선택으로 유도하지 않는지 여부

질문을 먼저 중립적으로 세우고 답을 채웠다. "왜 X를 안 썼나" 같은 유도형 대신 "무엇이 이 선택을 정당화하는가"로 물었다.

## Neutral Question Flow (중립 질문 흐름)

| 영역 | 중립적 질문 | 답변 | 근거 | Recommended Answer (권장 답변) |
| --- | --- | --- | --- | --- |
| 상태 계약 소유 | 예약 상태 6종 유니온은 어느 계층이 소유해야 하는가 | 현재는 UI(`ui/parts/reservationStatus.ts`)가 소유한다 | `model/reservation.ts`는 4종만 정의해 `REJECTED`·`COMPLETED`가 없고, model 확장은 Logic 경계다 | 서버 계약 확정 시 model로 이전. 그때까지 UI 소유를 유지하되 handoff에 이전 대상으로 기록 |
| 표시 회귀 | 상태 맵 추출이 목록 카드 표시를 바꿨는가 | 공백 `statusLabel` 처리만 달라졌다 | 기존은 `??`만 써서 공백이면 배지가 `-`로 비었고, 지금은 기본 라벨로 대체된다 | 개선 방향이므로 유지. 목록 테스트가 없어 자동 검출이 안 된다는 점을 evaluation-log에 기록 |
| 마크업 선택 | 용어-값 쌍을 무엇으로 그리는 것이 적절한가 | `dl > div > dt/dd` | 표가 아니라 용어-설명 쌍이고 낭독 순서가 자연스럽다. `div` 래퍼는 표준 허용이며 그리드 정렬에 필요하다 | `<dl>` 유지 |
| 식별자 충돌 | 섹션 제목 id가 중복될 수 있는가 | 초안의 입장 코드 섹션은 하드코딩 id였다 | 같은 화면이 두 번 렌더되면 `aria-labelledby`가 깨진다 | `useId`로 교체(적용 완료) |
| 권한 판정 위치 | 취소 가능 판정을 UI가 계산해도 되는가 | 아니다. `canCancel` boolean만 받는다 | Figma STEP07 02행이 "예약자 본인·상태·현재<T-5를 최종 클릭 순간 재검증"으로 서버 판정을 명시한다 | 서버 `cancelable` 수신 유지. 클라이언트 재현은 시계 오차에 취약 |
| 디자인 충돌 | 프레임 11px 문구를 그대로 쓸 것인가 | 12px로 올렸다 | DESIGN.md "본문 14px 미만 새로 도입 금지, 12px는 대비 충분한 메타데이터만" | DESIGN.md 우선(사용자 지시와 일치) |
| 범위 판단 | 코드 복사 버튼을 남길 이유가 있는가 | 없어서 제거했다 | STEP06 프레임에 복사 버튼이 없다. 1차 구현에서 임의로 추가한 것이었다 | 제거 유지. 필요하면 디자인 변경이 선행 |
| 팝업 문구 분기 | 취소 완료의 코드 폐기 문구를 항상 보여도 되는가 | 아니다. `inviteCodeRevoked`로 분기했다 | STEP08 02행 "승인대기 취소: 알림 없음 / 승인완료 취소: 코드 폐기" | 조건부 표시 유지 |
| 검증 신뢰도 | 전체 테스트 6건 실패를 이번 변경 탓으로 볼 수 있는가 | 아니다 | 실패는 모두 `citizen-participation`의 MSW `onUnhandledRequest` 문제이고 변경 파일과 의존 관계가 없다 | 무관함을 근거와 함께 기록하고 별도 작업으로 분리 |
| 배선 책임 | 취소 확인→API→완료 흐름을 UI가 들고 있어야 하는가 | 아니다. 팝업 open 상태와 콜백만 노출한다 | 상태 전이와 API 호출은 Logic 경계 | 호출부(라우트) 책임으로 handoff에 명시 |

## 결론

구조·문구·권한 경계 모두 프레임과 정의서에 근거를 두고 결정했고, 프레임과 DESIGN.md가 충돌한 4곳은 DESIGN.md를 따랐다. 검토 중 발견한 하드코딩 id는 즉시 고쳤다. 남은 약점은 목록 카드의 표시 회귀를 잡아 줄 테스트가 없다는 점이며 evaluation-log에 후속 항목으로 남겼다.
