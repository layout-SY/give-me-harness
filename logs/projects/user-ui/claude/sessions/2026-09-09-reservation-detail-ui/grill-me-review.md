# 자기 반박 검토 — 예약 상세 UI

## 지적과 대응

**1. 상태 정의 추출이 목록 동작을 바꾸지 않았나?**
`ReservationCard`는 기존에 `item.statusLabel ?? STATUS_LABEL[...]`을 썼고, 지금은 공백 문자열도 기본 라벨로 대체한다. 공백 라벨은 `StatusBadge`가 `-`로 렌더하던 값이므로 변경은 개선 방향이며, 목록 테스트가 없어 회귀로 잡히지 않는다는 점은 evaluation-log에 남겼다. 유니온·톤·라벨 값 자체는 그대로다.

**2. `<dl>` 안의 `<div>` 래핑이 접근성을 해치지 않나?**
HTML 표준에서 `dl` 자식으로 `div` 래퍼는 허용되며, 항목별 그리드 정렬에 필요하다. `dt`/`dd` 쌍은 유지된다.

**3. 섹션 제목 id 충돌 가능성**
초안은 참여 코드 섹션에 하드코딩 id를 썼다. 같은 화면이 두 번 렌더되면 중복 id가 되므로 `useId`로 교체했다. `ReservationDetailSection`은 처음부터 `useId`를 쓴다.

**4. 항목이 비면 아무것도 안 보이는 화면이 되지 않나?**
상태 배지와 회의명은 섹션과 무관하게 항상 그린다. 다만 모든 props가 비면 헤더와 배지만 남는데, 이는 데이터가 없는 비정상 상태이므로 UI에서 별도 빈 상태를 만들지 않고 호출부의 `errorMessage`/`isLoading` 분기에 맡겼다.

**5. `canCancel`이 아니라 상태로 판정하는 게 간단하지 않나?**
간단하지만 UI가 취소 정책(승인대기만 취소 가능인지, 시작 N시간 전까지인지)을 소유하게 된다. 정책은 서버·Logic 소유라 boolean 수신을 유지했다.

**6. 참여 코드 복사 결과 피드백이 없다**
`onCopyInviteCode` 호출만 하고 토스트·문구를 띄우지 않는다. 복사 성공 여부는 클립보드 API 결과에 달려 있어 Logic이 알려 줘야 한다. 후속 계약으로 남겼다.

**7. 검증이 충분한가?**
표시·빈 값 생략·상태 라벨 대체·취소 노출 분기·코드 복사·오류·로딩·뒤로가기 9케이스를 덮었다. 전체 테스트의 6개 실패는 `citizen-participation` MSW 문제로 이번 변경 파일과 무관함을 실패 목록으로 확인했다.
