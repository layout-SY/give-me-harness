# Grill Me 검토

## Method Guardrails (검토 방법 안전장치)

- [x] neutral question-first 적용 여부
- [x] 질문이 검토자를 특정 구현 선택으로 유도하지 않는지 여부

별도 grill-me 인터뷰 세션은 열지 않았다. 아래 행은 구현 전에 사용자 대화에서 닫힌 분기와, 사용자가 스키마를 주지 않아 가정한 분기만 기록한다.

## Neutral Question Flow (중립 질문 흐름)

| 영역 | 중립적 질문 | 답변 | 근거 | Recommended Answer (권장 답변) |
| --- | --- | --- | --- | --- |
| 식별자 | 로그인 값은 이메일인가 일반 문자열인가? | 일반 문자열 `loginId` | 사용자: 로그인 페이지 값은 이메일이 아닌 일반 문자열, 본문 예시 `loginId` | 이메일 검증을 제거하고 `loginId`를 보낸다 |
| 전송 | 로그인은 인증이 필요한가? | 인증 없이 호출 | 사용자: 인증 없이 호출한다 | 인증 Axios에 Bearer 인터셉터를 두지 않는다 |
| 갱신 | 액세스 토큰은 어떻게 유지하는가? | `expiresIn` 전에 `POST /auth/refresh` | 사용자 스펙 | 만료 시각을 저장하고 만료 전에 refresh한다 |
| 오류 | 아이디 없음과 비밀번호 틀림을 구분하는가? | 응답이 같다 | 사용자 스펙 | 클라이언트 분기를 만들지 않는다 |
| 리프레시 본문 | refresh 요청에 무엇을 넣는가? | 사용자 미제공 | 스펙에 본문 예시 없음 | `{ refreshToken }` 본문으로 가정한다 |

## 결론

닫힌 분기는 구현에 반영했다. 열려 있는 것은 refresh 요청 본문·응답 공식 스키마와 리프레시 실패 시 세션 처리다.
