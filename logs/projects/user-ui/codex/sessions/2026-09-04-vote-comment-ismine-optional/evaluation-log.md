# 평가 로그

## 현재 판정과의 경계

여기서는 Watcher 판정을 다시 평가하지 않는다. 아래는 merge를 차단하지 않는 후속 관찰이다.

## 장기 관찰 사항

- vote comment `isMine`은 곧 필수로 돌아갈 예정이다. optional을 오래 두면 소유권 없는 수정/삭제 UI가 정상처럼 보일 수 있다.
- `commentSchema`와 `voteCommentSchema`가 같은 소유권 필드를 서로 다른 파일에서 정의한다. 백엔드가 필드를 넣으면 두 스키마를 같은 필수 수준으로 맞출 필요가 있다.
- 개발 `[api-failure]` 로그가 Zod path를 `<field>`로 가려 계약 불일치 위치를 바로 못 본다.

## 목록에 등록할 재사용 가능 자산

- 현재 등록할 공용 UI 또는 hook 자산은 없다.
- optional 소유권 필드를 공용 헬퍼로 빼지 않는다. 사용처가 스키마 두 곳뿐이고 생명주기가 백엔드 배포에 묶여 있다.

## 기술 부채

1. 백엔드 `isMine` 배포 후 `voteCommentSchema`를 다시 필수로 올리고 거절 테스트를 복원해야 한다.
2. 진단 로그가 스키마 필드명을 남기지 않아 같은 종류의 계약 오류를 재현하기 어렵다.
3. 전체 테스트 스위트에 vote ballot 선택지와 결과 라우트 timeout 실패가 남아 있다. 이번 작업과 무관하다.

## 프로세스 개선 사항

- 백엔드 필드 보류를 클라이언트가 필수로 고정하면 목록 전체가 사라진다. 신규 필드는 배포 전까지 optional로 두고, 배포 확인 후 필수로 올리는 순서를 계약 체크리스트에 넣을 수 있다.

## 권고 사항

1. **P1:** 백엔드가 `isMine`을 내려주기 시작하면 `voteCommentSchema`를 필수로 되돌리고 거절 테스트를 복원한다.
2. **P2:** 개발 Zod 진단 path에 안전한 식별자 필드명과 배열 인덱스를 남긴다.
3. **P3:** `postVote` 선택지 계약과 `CitizenResultRoutes` timeout 실패를 별도 브랜치에서 조사한다.
