# 평가 로그

## 현재 판정과의 경계

현재 변경의 통과 여부는 review-log와 실행 결과에서 다룬다. 아래는 후속 개선 제안이며 이번 작업에 추가 구현하지 않는다.

## 장기 관찰 및 권고

| 관찰 | 유지 시 실제 문제 | 개선 시 추가 복잡성 | 권고 |
| --- | --- | --- | --- |
| 실제 API 명세 부재 | 엄격한 DTO와 backend 응답이 어긋나면 화면을 로드할 수 없음 | 명세 관리와 계약 대조 비용 | backend 확정 시 현재 추정 DTO·MSW와 대조 |
| 시민참여 기존 테스트 6개 실패 | 전체 CI의 새 실패를 구별하기 어려움 | 해당 기능의 요청·응답 및 MSW 원인 조사 | 별도 Logic 작업으로 회귀 복구 |
| 상태 표시 라벨이 UI·parser에 존재 | 새 상태 추가 시 표시가 불일치할 수 있음 | UI 소유 파일 계약 변경 및 이관 | 실제 계약 확정 시 모델 상태와 UI 라벨 소유권 공동 정리 |
| mock의 현재 사용자·제한은 주입 설정 | 여러 계정의 실제 권한 차이를 검증하지 못함 | 인증 subject 기반 fixture 설계 | 실제 서버 인증 계약 확정 후 확장 |

## 구조 및 의존성

새 라이브러리나 범용 hook을 추가하지 않았다. 전송·파싱은 feature api, query·상태는 hook, 표현은 기존 UI, 연결은 pages가 소유한다. 현재 재사용 수요로는 별도 공용 프레임워크가 필요하지 않다.

## 프로세스 개선

브랜치 제안 전에 launcher의 실제 세션 산출물 경로를 확인해야 한다. 이번에는 자동 귀속 경로와 작업명 기반 폴더를 혼동해 불필요하게 작업을 멈췄다. 등록된 경로를 사용해 해결했으며 중앙 정책 자체는 변경하지 않았다.

명령 승인 요청에는 대기 기록의 30분 유효기간과 실제 만료 시각을 함께 안내해야 한다. 이번에는 만료 후 도착한 승인 두 건이 반영되지 않았고, 유효기간 내 재승인으로 해소됐다. 중앙 정책 개선 작업에서는 만료 원인을 명시적으로 안내하는 동작을 검토할 수 있다. 이 세션에서는 중앙 정책을 변경하지 않았다.
