# 평가 로그

## 현재 판정과의 경계

현재 변경의 판정은 review-log.md에 기록했다. 이 문서는 추가 구현이나 scope 확대를 승인하지 않는다.

## 장기 관찰과 권고

| 관찰 | 채택하지 않으면 남는 문제 | 권고와 추가 비용 |
| --- | --- | --- |
| 투표 API와 mock 경로가 달라 기존 테스트 5개 실패 | 전체 테스트가 항상 실패해 새 회귀 판단이 어려워진다 | 별도 투표 계약 작업에서 실제 명세와 API·mock·HTTP 테스트를 함께 맞춘다. 계약 확인과 회귀 검증 비용이 필요하다 |
| 토론 wire DTO는 화면 근거의 임시 계약 | 실제 backend 응답이 다르면 parser 단계에서 요청이 실패한다 | backend 명세 확정 후 현재 API 경계와 HTTP 테스트를 같이 갱신한다. 새 추상화보다 기존 도메인 파일 수정이 적합하다 |
| Zod optional과 exactOptionalPropertyTypes의 표현 차이 | 비슷한 DTO를 공통 함수에 넘길 때 다시 타입 충돌할 수 있다 | 인접 조건부 속성 구성 패턴을 사용한다. 공용 helper 도입은 반복 사례와 타입 복잡성을 먼저 확인한다 |
| JS 번들 2,472.94 kB, gzip 722.05 kB 경고 | 초기 로딩 비용이 커질 가능성이 있다. 실제 사용자 영향은 미측정이다 | 별도 성능 측정 이후 route 분할을 검토한다. 분할·로딩·오류 처리 경로가 추가된다 |

## 재사용과 의존 방향

기존 ApiClient·ApiResult, 도메인별 parser, TanStack Query key와 기존 UI props/callback을 유지한다. 이번 타입 수정을 위해 공용 DTO나 추상화 범위를 넓히지 않았다.

## 프로세스

이번 빌드 명령 승인은 새 assignment의 동일 worktree에서 정상 소비되어 빌드가 성공했다. 이전 세션 승인 훅 결함이 중앙에서 수정됐다고 단정할 근거는 없다. 테스트의 로컬 서버는 sandbox 외부 실행 권한이 필요함을 기록해 환경 오류와 코드 실패를 구분한다.

## 다음 제안 단계

현재 작업은 커밋과 병합 최종 계약 승인 절차를 진행한다. 투표 계약 정합성과 실제 backend 호환 확인은 별도 후속 작업 후보이며 이번 요청에서 구현하지 않는다.
