# 포트폴리오 기록

## 사용자 요구

"현재 구현에서 login 페이지 없지?" — 로그인 화면 존재 여부 확인 요청. 부재 확인 후 "작업 진행" 으로 신설 승인.

## 문제 근거 (추정 아닌 확인된 사실)

- `src/pages/` 에 로그인 슬라이스 없음, `routes.tsx` 에 `/sign-in` 라우트 없음.
- `src/app/router/private-route.tsx:11` 과 `src/widgets/app-header/ui/header.tsx:18` 은 이미 `/sign-in` 으로 이동.
- 인증 API·훅·세션 저장소는 이미 구현되어 있고 화면만 비어 있는 상태였다.

## 검토한 대안과 선택 이유

**범위** — A: 로그인 화면만 신설 / B: `PrivateRoute` 까지 연결.
→ A 선택. B는 미인증 시 전 관리자 화면이 리다이렉트되어 개발 중 화면 확인 흐름이 끊긴다.
확실한 결함(로그아웃 후 빈 경로)만 먼저 닫고, 접근 제어는 mock 환경 우회 방식까지 정한 뒤 별도로 처리하는 편이 되돌리기 쉽다.

**폼 구현** — react-hook-form 어댑터 / controlled state.
→ `shared/ui/form` 이 패키지 미설치 placeholder 라 사용 불가. 필드 2개 화면에 패키지를 도입하는 것은 과하다고 보고 controlled state 로 처리.

**오류 표시** — 전역 다이얼로그 / 인라인 메시지.
→ `use-api.tsx` 를 읽어 `onError` 가 있으면 전역 다이얼로그가 뜨지 않고 예외가 전파된다는 것을 확인했다.
전역 경로가 동작하지 않으므로 인라인이 유일한 선택이었다. 추측이 아니라 코드 확인으로 결정했다.

## 실제 구현

`SignInController` 계약을 두고 View(표현)와 hook(상태·제출)을 분리했다. 인증은 기존 `useAuth().getAuthentication` 에 위임해
토큰·세션 로직을 화면 계층에 복제하지 않았다.

- 실패 메시지를 전송 실패 / 401·403 / 그 외 서버 오류로 나눴다. 401·403 을 뭉뚱그린 것은 계정 열거를 막기 위한 의도적 선택이다.
- 접근성: label↔id 연결, `autoComplete` 지정, 오류 영역 `role="alert"` + `aria-live`, 오류 영역 `min-height` 로 레이아웃 흔들림 제거.
- 디자인: 신규 색상 토큰 도입이 정책상 금지라 기존 팔레트만 사용했고, 카드 상단 브랜드 밴드에 좌측 GNB 와 같은 면색을 써서
  로그인 전후 화면이 같은 제품으로 읽히게 했다. 강조는 제출 버튼 한 곳으로 제한했다.

## 검증 결과

- `npm run build` 통과(`tsc -b` 타입 검증 포함).
- `npm run lint` 신규·수정 경로 지적 0건. 저장소 전체 68 error 는 이번 변경 이전부터 존재.
- 브라우저 시각 QA 와 런타임 로그인 성공/실패 실측은 수행하지 않았다. 실제 서버 응답 기준 동작은 미확인 상태다.
