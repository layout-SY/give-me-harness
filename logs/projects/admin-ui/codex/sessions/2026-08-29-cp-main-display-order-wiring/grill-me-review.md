# Grill Me 검토

## Method Guardrails (검토 방법 안전장치)

- [x] neutral question-first 적용 여부
- [x] 질문이 검토자를 특정 구현 선택으로 유도하지 않는지 여부

## Neutral Question Flow (중립 질문 흐름)

| 영역 | 중립적 질문 | 답변 | 근거 | Recommended Answer (권장 답변) |
| --- | --- | --- | --- | --- |
| 상태 모델 | 순서 변경 여부는 어떤 값으로 판별해야 하는가? | 항목 식별자·제목과 함께 `order` 차이를 비교한다. | 순서만 바꾼 뒤 저장 버튼이 활성화되어야 한다. | `order`를 dirty 비교에 포함한다. |
| 경계 조건 | 첫 항목의 위 이동과 마지막 항목의 아래 이동은 어떻게 처리되는가? | 이동 가능 여부를 계산해 UI와 모델 모두에서 차단한다. | 회귀 테스트와 브라우저 disabled 상태 확인 | 이중 경계 보호를 유지한다. |
| 저장 계약 | 잘못된 순서 payload가 성공 처리될 가능성은 없는가? | MSW handler가 순서 집합과 중복을 검증한다. | 중복 order 거부 테스트 통과 | handler 검증을 유지한다. |
| 저장 후 상태 | 성공 응답 이후 dirty 상태는 어떻게 해제되는가? | 응답을 기준 상태와 draft에 동기화한다. | 저장 후 버튼 disabled 복귀 확인 | 서버 응답을 단일 동기화 기준으로 사용한다. |
| 추상화 | 순서 이동을 즉시 공용 자산으로 분리해야 하는가? | 현재 단일 도메인 사용만 확인되어 분리하지 않았다. | 재사용 근거 부족 | 두 번째 실제 사용처가 생길 때 검토한다. |

## 결론

현재 구현은 경계, dirty, 저장 계약, 저장 후 동기화를 모두 검증했으며 요구 범위를 벗어난 추상화를 추가하지 않았다.
