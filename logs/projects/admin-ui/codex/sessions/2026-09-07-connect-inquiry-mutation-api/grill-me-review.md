# Grill Me 검토

## 검토 방법 안전장치

- 중립 질문으로 계약과 결과를 점검했다.
- 사용자에게 누락 계약만 질문하여 답변 없음의 실제 표현이 null임을 확인했다.

## 중립 질문 흐름

| 영역 | 중립적 질문 | 답변 | 근거 | 권장 답변 |
| --- | --- | --- | --- | --- |
| 응답 | 답변 없음은 어떤 응답인가? | null | 사용자의 명시적 답변 | null을 보존하고 UI에서 NoResults 표시 |
| 전송 | 실제로 허용되는 답변 body는 무엇인가? | content 문자열만 포함한 JSON | 제공된 POST/PUT 명세와 transport 테스트 | 과거 message·파일·이메일 필드를 제외 |
| 캐시 | mutation 결과로 상세를 대체할 수 있는가? | 불가, data는 문자열 | 제공 응답 명세 | 성공 후 관련 조회 갱신 |
| 삭제 | 먼저 시작한 상세 조회가 나중에 끝나면 어떻게 되는가? | 취소하고 상세 캐시 제거 | 실제 QueryClient 취소·지연 응답 테스트 | 삭제된 데이터를 다시 표시하지 않게 처리 |
| 상태 | 답변 변경과 상태 변경이 자동으로 연결되는가? | 제공된 계약에 없음 | 별도 PATCH 명세 | API 두 개의 의도를 분리하고 재조회 결과 사용 |
| 검증 | 전체 lint 실패가 새 변경 때문인가? | 실패 파일들은 변경되지 않음 | 전체 lint 및 sy-main 대비 경로 diff, 대상 lint 통과 | 기존 문제를 고지하고 scope 밖 코드를 수정하지 않음 |

## 결론

Logic 변경은 제공된 계약과 사용자 확인에 맞는다. UI 연결은 별도 담당자의 작업으로 남기고 실제 서버의 미제공 업무 오류 계약은 추정한 mock과 구분하여 인계한다.
