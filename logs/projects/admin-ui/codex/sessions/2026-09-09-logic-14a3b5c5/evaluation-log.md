# 장기 평가 기록

페이지 상태와 API 계약의 경계를 유지했다. 구현자의 관찰·권고이며 독립 PASS/FAIL 판정을 대신하지 않는다.

## 관찰

입력 draft·적용 URL·서버 캐시의 소유권을 분리했다. 편집한 필드만 draft에 보관해 재조회가 미저장 입력을 덮지 않는다. API 파싱·캐시는 entities, 이동·오류 표시는 controller, 표현은 View가 맡는다. 공용 store·새 의존성 없이 저장·삭제의 동일한 보호 규칙만 page-local로 추출했다.

## 권고

| 권고 | 미채택 시 남는 문제 | 추가 비용 | 우선순위 |
| --- | --- | --- | --- |
| UI 라우트·메뉴·MSW 실행 방식 연결 | 페이지 진입·mock 요청 처리 미완성 | 소유 파일 변경·연결 확인 | 필수 후속 |
| 기존 전체 lint·타입 오류 별도 해소 | 새 변경 검증이 기존 실패에 가려짐 | 범위·소유권 분리·회귀 검증 | 별도 품질 작업 |
| 연결 후 검색 복귀·삭제·ID 전환 확인 | SSR 밖의 이벤트·effect 미확인 | 실행 환경·기능 검증 시간 | UI 연결 직후 |
| pinned 집계 의미를 실 API 계약에 명시 | MSW 규칙을 서버 규칙으로 오해 가능 | API 담당과 근거 확인 | API 통합 시 |

공용화·테스트 프레임워크 추가는 현재 권고하지 않는다. 같은 사용처·검증 공백이 반복될 때 근거부터 기록한다. 사용자 기능 피드백·성능 측정 결과는 없다.
