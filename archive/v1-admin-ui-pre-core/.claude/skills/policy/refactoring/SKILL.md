# Refactoring (Policy)

## 언제 이 스킬을 사용하나요?

- 공용 컴포넌트/훅/유틸을 추출하거나 이동할 때
- 중복 코드/죽은 코드 제거 작업을 수행할 때
- 레거시 모듈을 리팩터하되 **기능은 보존**해야 할 때

## Principles

- **안전한 리팩토링 기준 우선** (테스트/빌드/타입이 깨지지 않는 변경부터)
- **공통화 조건 충족 시에만 추출**:
  - 2개 이상 도메인에서 실제 재사용 사례가 존재
  - props/타입이 제네릭화 가능
  - 도메인 결합이 약함
- **현재 범위 vs 후속 범위 분리** (이번 PR에 포함할 범위를 명시적으로 선언)
- 레거시 대응 시 **기능 변경 금지** (행동 보존, 내부 구조만 개선)

## 금지

- 사용처 1곳만 있는 코드를 선제 추출
- 리팩터 중 API 시그니처 변경(호출부 계약 파손)
- 기능 변경을 리팩터로 위장 (기능 변경은 구현 작업 범위)
- 범위 불명확한 대규모 일괄 수정
