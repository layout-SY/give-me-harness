# Publishing (Policy)

## 언제 이 스킬을 사용하나요?

- 신규 UI 구조/레이아웃/props 계약을 설계할 때
- 기존 마크업을 재구성하거나 접근성 속성을 보강할 때
- 도메인 로직 없이 **이벤트 핸들러 인터페이스만** 정의해야 할 때

## Principles

- HTML/CSS 기본 원칙 준수 (시맨틱 요소 우선, 유효 구조 유지)
- 접근성 속성 준수 (`aria-*`, `role`, 포커스 순서)
- **스타일 재사용 우선** (공용 컴포넌트 스타일 먼저 검토)
- **이벤트 인터페이스만 정의**한다 (`onSubmit`, `onClose` 등 시그니처)
- 도메인 로직(API 호출, DTO 매핑, 검증 로직) **구현 금지** — 기능 구현 단계에서 담당

## 금지

- UI 설계 단계에서 `src/apis` 호출부를 직접 추가
- 도메인 enum/DTO 신규 정의
- 공용 컴포넌트의 기존 props 계약 변경 (구조 개선 단계로 분리)
