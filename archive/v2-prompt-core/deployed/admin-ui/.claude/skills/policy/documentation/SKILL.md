# Documentation (Policy)

## 언제 이 스킬을 사용하나요?

- 작업 흐름에서 단계 전환 직전/직후
- 리팩터·대규모 변경의 근거/결정을 기록으로 남길 때
- 디버그/장애 로그를 작성할 때

## 규칙

- 단계별 **필수 문서**를 남긴다 (계획/변경/검증 결과)
- 로그는 **결론 중심**으로 작성한다 (무엇을 했고 왜 했는지)
- 순차적 개선점·논리적 근거는 반드시 남긴다 (왜 이 방향인지)
- 동일 주제의 문서가 여러 곳에 중복 생성되지 않도록 기존 문서 우선 갱신

## 금지

- 불필요한 진행 스트림 로그(타임라인 덤프) 생성
- 변경 의도/근거 없이 코드 diff만 붙인 문서
- 문서 예시의 사용자 노출 문자열은 한글로 직접 작성한다 (프로젝트는 i18n 미사용, 단일 한국어)
