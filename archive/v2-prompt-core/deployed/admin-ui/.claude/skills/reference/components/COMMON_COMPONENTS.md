# Common Components Selection Guide

## 목적

이 문서는 에이전트가 "재사용성을 높여라 / 공용 컴포넌트를 써라"는 요구를 수용했을 때,
**어떤 요구사항에 어떤 공용 컴포넌트를 선택할지** 결정하기 위한 선택 가이드다.

> 선택 후의 상세 사용법은 각 컴포넌트 폴더의 `SKILL.md`를 반드시 확인한다.
> DAO/Activity/Dashboard 등 **도메인 전용 공용 컴포넌트**는 `DOMAIN_COMPONENTS.md`를 본다.

---

## 1) 요구사항 -> 컴포넌트 선택 매트릭스

### 입력/폼

- 일반 텍스트 입력: `text-input`
- 멀티라인 입력: `text-area`
- 드롭다운 선택: `dropdown`
- 온/오프 토글: `toggle-switch`
- 리치 텍스트 편집: `text-editor`
- 일반 액션 버튼: `button`, `icon-button`

### 목록/검색

- 표준 테이블(컬럼 정의 기반): `table`
- 테이블 fetch 어댑터: `table/hooks/useFetchAdapter`
- 검색 + 탭 + 생성 버튼 상단바: `search-state-bar`
- 페이지네이션: `pagination`
- 빈 상태: `no-results`
- 로딩 오버레이: `loading`

### 모달/오버레이

- 중앙형 모달: `modal`
- 우측 상세 편집 모달: `side-modal`
- 단순 팝업/선택 팝업: `popup`
- 이미지 미리보기: `image-modal`
- 이미지 파일 선택 팝업(콜백형): `image-upload`
- 부드러운 등장 효과: `fade-in`
- 날짜 범위 선택: `calendar-picker`

### 전역/레이아웃

- 상단 바/로그아웃: `header`
- 좌측 내비게이션: `navigation`
- 인증 가드: `private-route`
- 권한 가드: `role-based-route`

### 도메인 공용 오버레이

- 유저 선택 팝업: `select-users`
- 우편/보상 발송 팝업: `send-parcel`

## 2) 선택 규칙

1. 요구사항에 70% 이상 맞는 공용 컴포넌트가 있으면 우선 재사용한다.
2. 기존 컴포넌트가 동작은 맞지만 스타일/세부 인터랙션이 부족하면:
   - 공용 컴포넌트는 유지하고
   - 페이지 레벨에서 보조 래퍼/스타일을 추가한다.
3. 공용 컴포넌트의 계약을 깨지 않는 선에서 props 확장한다.
4. 특정 페이지의 비즈니스 규칙(API DTO, pubsub 이벤트)에 강결합되면 페이지 컴포넌트로 둔다.

---

## 3) 중요 주의사항 (완성도 이슈 반영)

현재 일부 공용 컴포넌트는 완성도가 높지 않아 다음을 허용한다.

1. 요구사항을 맞추기 위해 페이지에서 추가 스타일 구현
2. 공용 컴포넌트 위에 얇은 래퍼 컴포넌트 작성
3. 공용 컴포넌트 소규모 보강(props/className 추가)

단, 아래는 금지:

1. 기존 화면이 깨질 수 있는 대규모 공용 스타일 변경
2. 공용 컴포넌트 계약과 다른 독자 사용 패턴 도입
3. 사용자 노출 문자열을 한글이 아닌 언어로 작성

---

## 4) 선택 후 필수 행동

1. 선택한 컴포넌트의 개별 가이드 파일을 읽는다.
2. 해당 `SKILL.md`의 props/주의사항을 준수해 구현한다.
3. 기존 사용처와 충돌 없는지 최소 영향 검증을 수행한다.
