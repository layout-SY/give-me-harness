# Codex 네이티브 품질

## 개발

- 구현 전에 결과에 중대한 영향을 주는 모호함을 해소한다.
- 유사한 기능, 공용 UI, 데이터 흐름 및 오류 처리를 먼저 조사한다.
- 최소 변경안, 균형안 및 구조 개선안을 비교한 뒤 추가 결정이 필요 없는 하나의 설계를 선택한다.
- 명시적인 승인을 받기 전에는 구현하지 않는다.

## 리뷰

- 실제 사용자에게 영향을 주거나 명시적인 정책을 위반한 현재 변경의 결함만 보고한다.
- 확신도가 80%를 넘는 발견 사항에는 파일 수준의 근거, 영향 및 구체적인 수정안을 반드시 제시한다.
- 취향에만 근거한 지적, 기존 결함 또는 정적 분석이나 타입 검사에서 이미 강제하는 문제로 리뷰를 부풀리지 않는다.

## 조용한 실패 및 타입 설계

- 비어 있거나 지나치게 넓은 예외 포착 후 무시 동작과 설명되지 않은 대체 동작을 허용하지 않는다.
- 디버깅 맥락을 보존하고, 오류가 사용자에게 노출될 때는 사용자가 대응할 수 있는 오류를 제공한다.
- 불변 조건을 단순히 설명하는 주석보다 해당 조건을 강제하는 타입과 파싱 경계를 우선한다.
- 더 강한 모델링이 예방하는 문제보다 더 큰 복잡성을 초래한다면 단순한 타입을 유지한다.

## 단순화 및 프런트엔드 품질

- 동작을 보존하면서 중첩, 중복, 과도한 추상화 및 모호한 이름을 줄인다.
- 관련 없는 정리는 별도로 승인받은 리팩터링에서 수행한다.
- `DESIGN.md`를 따른다. 접근성, 반응형 대응 및 성능을 미적 요소보다 후순위로 두지 않는다.
- 획일적인 시각적 기본값을 피하고 의도에 맞는 색상, 서체, 간격 및 움직임을 사용한다.
