# 이력서·포트폴리오 기록

## 사례 1 — 멀티 호스트 필수 산출물의 중앙 Git 아카이브 구축

- 작업 유형: AI 하네스·운영 자동화
- 관련 도메인/서비스: `asan-metaverse-user-ui`, `asan-metaverse-admin-ui`, Codex, Claude Code, OpenCode
- 문제 출처: 사용자 요구 | 구조 개선 | 운영 일관성

### 문제 상황

- 사용자가 제시한 구현·수정 요구: 프로젝트 내부 `logs`에 생성되는 필수 산출물을 중앙 정책 프로젝트에도 복사해 프로젝트와 별개의 Git으로 관리해야 했다.
- 테스트·실행에서 관찰한 문제: 기존 중앙 Git 청결 판정은 모든 미커밋 파일을 정책 sync 차단 사유로 보므로 자동 로그가 생성될 때마다 정책 배포까지 막히는 구조적 충돌이 있었다.
- 필요한 기술·구조가 없을 때 예상되는 문제: 네 개의 병렬 세션에서 생성된 설계·검토 근거가 프로젝트별 Git에만 흩어지고, 중앙 정책의 변경 이력과 작업 근거를 함께 추적할 수 없다.

### 고민과 선택

- 사용자 제안: 필수 산출물이 프로젝트 로그에 들어가면 중앙 시스템에도 그대로 복사하여 별도 Git에서 관리한다.
- 에이전트 제안: 프로젝트 로그를 활성 원본으로 유지하고 중앙에는 필수 8종만 단방향 증분 복사하며, host 종료 수명주기에 자동 연결한다.
- 검토한 대안: 전체 로그 폴더 동기화, 변경 로그만 기록한 뒤 다른 세션이 재해석하는 방식, 중앙 자동 Git commit, 원본 삭제까지 반영하는 양방향 동기화.
- 최종 선택: 폐쇄형 허용 목록, byte 비교, 원자 교체, 비삭제 아카이브, 수동 승인 Git 운영.
- 선택 이유와 제외 이유: 전체 복사는 transcript·이미지·임시 파일을 불필요하게 포함하고, 재해석 방식은 원문 일관성을 잃는다. 자동 Git과 양방향 삭제는 사용자 승인 정책 및 아카이브 목적과 충돌한다.

### 적용

- 변경 경로: 중앙 `lib/agent_policy`, `adapters/opencode`, `policy/common`, `adapters/claude`, `tests`, `logs`, 운영 문서.
- 구현·수정 내용: 프로젝트·채널 격리 수집기, 수동 CLI, 세 호스트 lifecycle 연결, 로그 전용 Git 청결 예외, 보안·회귀 테스트를 추가했다.
- 핵심 동작: 같은 파일은 건너뛰고 변경분만 원자적으로 복사하며, 중앙 사본을 자동 삭제하거나 Git에 자동 반영하지 않는다.

### 사용 기술과 구체적 목적

| 기술·구조·패턴 | 해결하려는 구체적 문제 | 적용 위치와 방식 |
| --- | --- | --- |
| Python `pathlib`와 폐쇄형 허용 목록 | 경로 밖 파일과 비필수 로그 유입 방지 | 직접 세션 디렉터리의 필수 8종만 선택 |
| byte 비교와 원자 교체 | 반복 종료의 불필요한 쓰기와 부분 파일 방지 | 동일 내용 skip, 임시 파일 fsync 후 `os.replace` |
| 호스트 lifecycle adapter | 네 세션에서 수동 복사 누락 방지 | Codex/Claude Stop, OpenCode `session.idle` |
| 프로젝트·채널 경로 격리 | 병렬 세션 로그 혼합 방지 | `{project}/{logic|claude}/sessions` |
| Git porcelain 경계 판정 | 로그 생성이 정책 배포를 막는 모순 제거 | `logs/**`만 미커밋 예외, 정책 소스는 계속 차단 |
| Python unittest·Node 구문·실설치 smoke | 파일 계약과 host adapter 회귀 방지 | 30개 테스트, plugin 구문과 OpenCode 1.18.19 config load 확인 |

### 결과

- 적용 전: 필수 산출물은 각 소비자 프로젝트 Git에만 존재했고 중앙 정책 저장소에는 자동 수집 경로가 없었다.
- 적용 후: 두 프로젝트·두 채널의 필수 산출물을 중앙 별도 Git 경로로 증분 보관할 수 있고, 세 호스트가 종료 수명주기에서 같은 수집기를 호출한다.
- 검증 결과: 중앙 단위 테스트 30개 PASS, 두 프로젝트 각 128 managed files audit PASS, OpenCode plugin Node 구문 검사와 설치본 smoke PASS. 최초 수집에서 필수 산출물 567개를 복사했고 즉시 재실행은 신규 복사 0개·unchanged 567개였다.
- 사용자 후속 피드백: 없음.
- 추가 요청 및 남은 제한: 소비자 sync는 별도 승인 대기, 자동 Git commit과 보존 정책은 범위 제외, legacy 불일치는 유지.

### 이력서·포트폴리오 문구

- 이력서 bullet: Codex·Claude Code·OpenCode 병렬 세션의 필수 산출물을 프로젝트·채널별로 격리해 중앙 Git에 증분 보관하는 lifecycle 기반 아카이브를 구현하고 30개 회귀 테스트로 검증.
- 포트폴리오 서술: 두 프런트엔드 저장소의 AI 작업 근거가 프로젝트별로 분산되는 문제를 해결하기 위해 활성 원본과 중앙 아카이브의 책임을 분리했다. 필수 8종만 byte 단위로 비교해 원자 복사하고, 세 호스트의 실제 종료 이벤트에 연결했으며, 로그 미커밋 상태가 정책 배포를 방해하지 않도록 Git 청결 판정을 분리했다. 자동 Git 작업과 양방향 삭제는 사용자 승인 및 보존 목적에 맞지 않아 제외했다.
