# 평가 로그

## 현재 판정과의 경계

여기서는 Watcher 판정을 다시 평가하지 않는다.

## 장기 관찰 사항

- 화면 URL은 `myActivity`, 서버 query는 `mine`이다. 라우트 상태가 서버 이름을 쓰지 않으면 이 불일치가 남는다.
- 내 활동 페이지는 제안 탭만 목록 `mine`을 쓰고 나머지는 `/me/activity`다. 백엔드가 페이지도 목록 query로 통일하면 전송 경로를 한 번 더 줄일 수 있다.
- 토론·정책 목록 params 매퍼가 두 API에 같다. 세 번째 사용처가 생기면 공유 여부를 재검토하면 된다.

## 목록에 등록할 재사용 가능 자산

없음. 새 공용 UI/훅을 추가하지 않았다.

## 기술 부채

- `toVoteListItemFromContent`는 목록 라우트에서 빠졌지만 매퍼 테스트에 남아 있다.
- 목록 카드 summary는 여전히 빈 문자열일 수 있다.

## 프로세스 개선 사항

목록 필터를 `/me/activity`로 분리한 직후 `mine` query로 되돌렸다. 필터 API를 화면 작업과 한 문서에 묶어 전달하면 DTO를 두 번 바꾸지 않아도 된다.

## 권고 사항

내 활동 페이지 응답이 확정되면 `/me/activity`와 목록 `mine`의 역할을 문서에 한 줄로 구분해 두면 다음 번 기획 변경 때 혼선이 줄어든다.
