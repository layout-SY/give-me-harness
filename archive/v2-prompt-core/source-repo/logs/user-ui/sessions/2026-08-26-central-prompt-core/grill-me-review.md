## Neutral Question Flow (중립 질문 흐름)

| 영역 | 중립적 질문 | 답변 | 근거 | Recommended Answer (권장 답변) |
| --- | --- | --- | --- | --- |
| 기존 자산 | 이미 존재하는 `asan-harness`를 재사용하지 않은 판단은 어떤 근거에 기반하는가 | 재사용하지 않았다 | `governance_sources.py`가 프롬프트 본문이 아닌 앵커 참조만 보유하고, `governance_render.py:40`의 `_root()`가 10줄 스텁을 생성하며 `render_command`가 이를 `os.replace`로 덮어쓴다. 현 상태 실행 시 지침이 소실된다 | 재사용하지 않는다 |
| 규모 | 200줄대 도구가 1,600줄 프롬프트를 관리하기에 부족하지 않은가 | 부족하지 않다 | 변환이 필요한 대상은 역할 정의 형식과 훅 등록뿐이고 나머지는 경로 매핑 복사다. 실제 구현은 260줄로 129개 파일을 결정적으로 배포했다 | 현 규모를 유지한다 |
| 강제력 | 훅 없이 배너만으로 편집을 막을 수 있는가 | 없다 | 배너는 모델이 따르는 소프트 규칙이다. 종료 코드 2 차단을 함께 두어야 실제로 막힌다. 검증에서 `AGENTS.md`와 스킬 편집이 exit 2로 차단됨을 확인했다 | 배너와 훅을 함께 둔다 |
| 삭제 정책 | `deploy`가 대상 디렉터리를 비우지 않아 잔여 파일이 남는 것은 결함인가 | 의도된 선택이다 | 비우면 `.codex/logs/**`와 `.codex/memory/**` 같은 프로젝트 소유 자산이 삭제된다. 대신 `check`가 미배포 신규 원본을 보고한다 | 덮어쓰기만 유지한다 |
| 잔여물 | admin-ui에 남은 `tanstack-query` 등 고유 스킬은 지금 삭제해야 하는가 | 삭제하지 않았다 | 인덱스인 `reference/SKILL.md`가 이를 나열하지 않아 참조 가능성이 낮고, 오버레이 기능 도입 시 복원 대상이다. `reserved/`에 사본을 보관했다 | 보류하고 P5에서 처리한다 |
| 호스트 통합 | 역할 정의를 호스트 하나로 통합하지 않은 것은 중앙화 목적에 어긋나지 않는가 | 어긋나지 않는다 | 해결 대상은 user-ui와 admin-ui 사이의 드리프트다. codex는 전체 범위, claude는 UI 한정 범위를 담당하므로 통합하면 역할 경계가 무너진다 | 호스트별로 유지한다 |
| 무결성 | 기존 SHA-256 훅 부트스트랩을 제거한 것은 보안 후퇴인가 | 제한적 후퇴다 | 훅 파일 변조 탐지 능력이 사라진다. 다만 해당 훅은 사용되지 않는 상태였고 사용자가 복잡도 축소를 요구했다. `sync.py check`가 해시 대조를 대신 수행한다 | 현 수준을 유지하되 제한을 문서화한다 |
| 검증 한계 | OpenCode 플러그인이 실제로 동작하는지 확인했는가 | 확인하지 못했다 | OpenCode 플러그인 API 규격을 실행 환경에서 검증하지 못했다. Python 브리지 로직은 codex와 동일하나 JS 어댑터는 미검증이다 | 제한 사항으로 명시한다 |
| 테스트 실패 | `npm run test`의 2건 실패를 이번 작업이 유발했는가 | 아니다 | `git status -- src package.json`이 비어 있어 애플리케이션 코드를 변경하지 않았음이 확인된다. 실패는 `resolveApiBaseUrl` 관련 사전 존재 실패다 | 수정하지 않고 보고한다 |
| 명령어 정합 | admin-ui에 `test` 스크립트가 없는데 `AGENTS.md`가 `npm run test`를 지시하는 것은 문제인가 | 문제다 | 배포된 프롬프트가 존재하지 않는 명령을 지시한다. 오버레이 부재로 인한 구조적 한계다 | 사용자에게 보고하고 P5에서 해결한다 |

## 결론

설계 판단은 근거를 유지한다. 다만 OpenCode 플러그인 미검증, SHA-256 무결성 축소, admin-ui의 `npm run test` 부재라는 세 가지 제한이 남으며 모두 `final-summary.md`에 기록한다.
