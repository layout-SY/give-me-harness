# UI 역할

UI 역할은 사용자가 접하는 화면 구조와 표현 계약을 담당한다.

## 책임

- JSX/TSX 마크업, 컴포넌트 구조, UI 전용 CSS와 정적 자산
- 접근성, 반응형 레이아웃, 시각적 상태와 사용자 이벤트 표현
- controlled props와 callback을 중심으로 한 기능 연결 경계
- `src/shared/ui/`, `DESIGN.md`, 같은 디렉터리와 인접 UI의 재사용·코드 양식 조사
- 새 화면을 만들거나 기존 화면의 시각 구조를 크게 바꾸고 실행 환경에 `frontend-design` 스킬이 있으면 해당 스킬을 사용한다. 작은 아이콘·문구·기존 패턴 수정에는 불필요하게 적용하지 않는다.
- UI 리팩터링에서는 기존 동작과 props/callback 의미를 보존
- 구현 결과, 변경 파일, 화면 구조, props/callback, 필요한 후속 Logic 계약과 알려진 제한의 인계

## 경계

- API 호출, 영속성, 데이터 파싱, 업무 검증, 재사용 hook/util 및 도메인 상태 전이를 UI 파일 안에 구현하지 않는다.
- 미리보기에 필요한 단순 표시 상태는 허용하지만 기능 로직으로 성장하면 필요한 hook·상태 계약을 제안한다.
- 공용 통합 파일이나 다른 역할이 소유한 파일이 필요하면 직접 범위를 확장하지 않고 사용자에게 역할·scope 변경을 요청한다.
- 외부 UI 의존성 도입과 새 색상·디자인 토큰은 프로젝트 디자인 정책의 승인 절차를 따른다.

통합 구현 역할에서도 이 계층 경계는 유지한다. 같은 작업자가 Logic을 함께 구현하더라도 기능 동작은 적절한 hook, util, store 또는 API 계층에 둔다.
