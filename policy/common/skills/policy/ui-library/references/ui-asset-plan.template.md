# UI 자산 선정 계획

현재 세션의 `unknown/ui-asset-plan.md`로 작성하고 `plan.md` 또는 `handoff.md`에서 연결한다. UI 구현 항목을 빠짐없이 작성하며 상세 기준은 상위 `SKILL.md`를 따른다.

## 작업과 조사 근거

- 요구사항·UI 구현 범위:
- 대상 project·branch·worktree·확인한 HEAD:
- 현재 스택·설치 버전의 근거 (`package.json`, lockfile, 설정):
- 조사한 공용 경로·인접 구현·다른 도메인의 실제 사용처:
- 적용한 디자인·상태 소유권·컴파일러 설정:
- 관련 계획·handoff와 현재 코드에서 다시 확인한 내용:

## 구현 항목별 선택

선택은 `기존 공용 자산 재사용`, `다른 도메인 자산 공용화`, `외부 라이브러리 사용`, `공용 자산 신규 작성` 중 기록한다. 미정·예외는 사유와 사용자에게 확인할 결정을 명시한다. 한 UI 항목에 자산이 여러 개면 행을 나눈다.

| 요구사항·UI 구현 항목 | 선택 | 자산·패키지·버전과 실제 경로 | 선택·제외 이유와 조사 근거 | 계약·예상 변경·검증 | 결정 상태·승인 근거 |
| --- | --- | --- | --- | --- | --- |

## 계약과 공용화 영향

- 항목별 props·이벤트 payload·callback·상태 소유권·접근성 계약:
- 공용 승격 시 기존 사용처·변경 경로·동작 보존·이전 방법:
- 신규 공용 자산의 요구사항상 공용 목적·재사용 대상·최소 공개 계약:
- 번들·의존성·렌더링·구독 영향과 측정 근거 또는 검증할 예상:
- 미확정 계약·부족한 자산·제외한 대안과 사용자에게 확인할 결정:

## UI·Logic 연결

UI와 API를 연결하면 `api-authoring/references/ui-controller.md`에 따라 작성하고 관련 계획·handoff에서 연결한다.

- 선행 구현·계약 제공자·근거 경로:
- 맞추는 방향: `controller <- UI` (Logic 선행) | `controller -> UI` (UI 선행)
- controller 공개 타입·구현 위치, 기준 UI·요청/응답 DTO와 양방향 매핑:
- UI 선행의 항목 불일치·사용자 질문·답변과 반영 또는 보류 상태:
