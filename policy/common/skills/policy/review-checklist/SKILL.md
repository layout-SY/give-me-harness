# 리뷰 점검표

목표 충족 범위, 승인 근거, 불러온 스킬, 타입 안전성, 검증 및 요청 데이터 완전성, 중복 로직, 렌더링 비용, 접근성, 빌드 및 정적 분석 결과, 문서화를 확인한다. UI 역할이 포함될 때만 `src/shared/ui/` 재사용과 디자인 정책을 필수 항목으로 적용한다. 파일 수준의 근거와 함께 PASS 또는 FAIL을 보고한다.

새 서비스 개념·API·요청/응답 필드·ID 매핑·기본값·업무 흐름에는 현재 프로젝트의 확인된 계약 또는 해당 결정을 확정한 사용자 답변이 있는지 확인한다. 재사용 자산이 없거나 부족했던 항목에도 확장·공용화·신규 작성 방식의 사용자 확인 근거가 있어야 한다. 근거 없이 채운 계약과 재사용 결정을 발견하면 해당 변경을 FAIL로 보고하고 질문으로 되돌린다. 자체 mock·fixture·타입 검사·빌드·테스트 통과를 서비스 계약의 근거로 인정하지 않는다.
