# 구현 품질

## 개발

- 서비스 정책·기획·데이터 계약의 모호함과 현재 프로젝트에서 확인하지 못한 필수 항목은 모두 사용자에게 질문하고 답변을 기다린다. 구현 도중 발견한 공백에도 공통 정책의 추측 금지 규칙을 적용한다.
- 유사한 기능, 공용 UI, 데이터 흐름 및 오류 처리를 먼저 조사한다.
- 재사용이 부족한 항목은 확장·공용화·신규 작성 대안과 영향을 비교해 사용자에게 방식을 확인받는다. 서비스 계약이나 재사용 방식이 미확정인 상태에서 “추가 결정이 필요 없는 설계”라고 간주해 선택하지 않는다.
- 명시적인 승인을 받기 전에는 구현하지 않는다.

## 코드 작업 후 자동 포맷 (필수)

- 페이지·컴포넌트·hook·기능의 코드 수정을 마치면 시스템 프롬프트에 안내된 `formatting.py apply`를 해당 worktree에서 실행한다. 실제 Prettier가 프로젝트의 `.prettierrc` 등 설정과 `.prettierignore`·`.gitignore`를 읽어 코드 파일을 자동 편집한다. 모델이 규칙을 해석해 띄어쓰기·줄바꿈을 수동으로 맞추는 것으로 대체하지 않는다.
- 정상 완료한 Write·Edit·apply_patch의 대상 파일만 하네스가 기록한다. 연결 worktree마다 실제 경로를 유지하며 포맷 실행은 현재 worktree의 기록만 처리한다. `prettier --write .` 같은 전체 프로젝트 포맷을 실행하지 않는다. source 외 host 정책·세션 로그·빌드 결과·node_modules는 대상에서 제외한다.
- 등록된 lint·test·build 명령의 PreToolUse에서도 미완료 포맷을 자동 실행한다. 포맷 후 변경된 파일을 다시 확인하고 검증한다. 검증 후 다시 수정했다면 포맷과 관련 검증을 다시 수행한다. stage·commit·병합 전에 포맷을 완료한다.
- 공용 실행기는 중앙 state의 고정 버전 Prettier를 사용한다. 소비자와 worktree마다 의존성을 복제하거나 `npx`로 최신 버전을 임의 설치하지 않는다. 엔진이 없으면 중앙의 `bin/agent-policy formatter-install`이 필요하다고 보고한다. 프로젝트 설정과 포맷 버전은 임의 변경하지 않는다.
- 포맷 전후의 파일·설정 해시와 마지막 수정 도구를 검사한다. 다른 쓰기가 진행 중이거나 기록 이후 내용이 바뀌었다면 덮어쓰지 않는다. 현재 내용을 읽고 승인된 구현을 마무리한 뒤 다시 실행한다. 이미 stage한 대상은 index와 working tree를 자동 변경하지 않고 포맷을 먼저 수행하도록 안내한다.
- 문법 오류·설정 누락·실행 실패·결과 미확인 쓰기는 포맷 완료로 간주하지 않는다. 오류와 해당 파일을 보고한다. 실패 시 기존 소스를 보존하며 빈 파일·이전 포맷 결과로 대체하지 않는다. 삭제된 파일을 재생성하지 않는다.
- 종료 시에도 누락을 검사한다. Codex·Claude는 미완료 포맷을 한 번 알리고 작업으로 돌아가도록 요청하되 같은 오류로 종료를 무한 반복시키지 않는다. OpenCode는 idle 이벤트에서 미완료 알림을 표시한다. 완료할 수 없으면 실제 미완료 사유를 최종 보고에 남긴다.
- 이 기록은 포맷 대상과 실행 결과를 식별할 뿐 세션에 branch 범위·소유권을 부여하지 않는다. 코드 수정 없이 기존 변경의 commit·merge만 수행하면 포맷 대상과 문서 의무를 새로 만들지 않는다.

## 리뷰

- 실제 사용자에게 영향을 주거나 명시적인 정책을 위반한 현재 변경의 결함만 보고한다.
- 확신도가 80%를 넘는 발견 사항에는 파일 수준의 근거, 영향 및 구체적인 수정안을 제시한다.
- 취향에만 근거한 지적, 기존 결함 또는 정적 분석이나 타입 검사에서 이미 강제하는 문제로 리뷰를 부풀리지 않는다.

## 조용한 실패 및 타입 설계

- 비어 있거나 지나치게 넓은 예외 포착 후 무시 동작과 설명되지 않은 대체 동작을 허용하지 않는다.
- 디버깅 맥락을 보존하고 오류가 사용자에게 노출될 때는 사용자가 대응할 수 있는 정보를 제공한다.
- 불변 조건을 설명하는 주석보다 해당 조건을 강제하는 타입과 파싱 경계를 우선한다.
- 더 강한 모델링이 예방하는 문제보다 큰 복잡성을 만들면 단순한 타입을 유지한다.

## 단순화 및 프런트엔드 품질

- 동작을 보존하면서 중첩, 중복, 과도한 추상화와 모호한 이름을 줄인다.
- 관련 없는 정리는 별도 승인받은 리팩터링에서 수행한다.
- `DESIGN.md`를 따르고 접근성, 반응형 대응과 성능을 미적 요소보다 후순위로 두지 않는다.
- 획일적인 시각 기본값을 피하고 의도에 맞는 색상, 서체, 간격과 움직임을 사용한다.
