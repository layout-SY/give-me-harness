# 토큰 사용량 보고서 구조

보고서는 `unknown/token-usage-report.md`에 아래 절을 이 순서로 쓴다. 표의 열은 그대로 두고, 값이 없으면 `—`로 적는다. 예시 값은 2026-10-15 admin-ui 세션 `swagger-api-명세-대조` 보고서에서 가져왔다.

## 머리말

- 제목: `# 토큰 사용량 보고 — 세션 <세션 산출물 이름> (브랜치·worktree별)`
- 작성일, host와 role, assignment, native session ID
- 기간(KST)과 총 시간, 자동 압축 횟수와 시각
- 범위: 처리한 작업 구간 수, 그중 branch·worktree가 있는 작업과 각 commit, 병합·정리 여부
- 이 분석 요청과 응답을 집계에서 뺐다는 문장과 `--until` 시각
- 집계 스크립트 경로와 작업 구간 파일 경로

## 0. 요약

번호 목록 5~8개. 각 항목은 굵은 한 문장의 결론과, 그 결론을 뒷받침하는 수치 1~3줄로 쓴다.

- 세션 전체 비용 환산, 부모와 하위 에이전트의 몫과 비중
- 가장 비싼 작업과 그 이유(파일당 비용을 다른 작업·이전 보고서와 비교)
- 가장 비싼 하위 에이전트 1~3개와 이유(응답 수, 평균 컨텍스트, 캐시 읽기)
- 재개·대기로 생긴 캐시 재기록의 합과 비중
- 응답당 도구 수의 변화와 그 원인에 대한 판단(확인 여부를 밝힌다)
- 부모 컨텍스트 관리(작업을 이어 처리한 비용, 긴 대기 뒤 재기록)
- 문서 재작성·통째 읽기 같은 반복 비용

예: "**세션 전체 비용 환산은 37.3M이다.** 부모가 9.33M(25%), 하위 에이전트 23개가 27.98M(75%)이다."

## 1. 집계 방법

| 항목 | 방법 |
| --- | --- |
| 부모 세션 | 기록 파일 경로, 집계 구간 |
| 하위 에이전트 | 기록 폴더와 개수 |
| 집계 단위 | 응답 1개당 usage 1회 |
| 출력 | 하한 계산 방식 |
| 비용 환산 | 가중치 식, 비교용이라는 설명 |
| 작업 구분 | 구간 파일 기준 |
| 재개 판정 | 4분 공백, 80% 재기록 |
| 도구 귀속 | 컨텍스트 차이의 비례 배분(±10%) |
| 범주 보정 | 세션·branch 이름이 범주 판정에 끼친 영향과 보정 |
| 모델·버전 | 부모·하위 에이전트의 모델과 host 버전, 정책 번들 변경 여부 |

## 2. 전체 합계

| 구분 | 응답 | 도구 | 캐시 신규 | 캐시 읽기 | 비캐시 입력 | 출력(하한) | 비용 환산 | 비중 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 부모 | | | | | | | | |
| 하위 에이전트 N개 | | | | | | | | |
| **합계** | | | | | | | | 100% |
| (참고) 이전 보고서의 작업 | | | | | | | | |

비용 구성 표(캐시 읽기 × 0.1, 캐시 신규 × 1.25, 출력 × 5를 부모·하위·전체로)와, 가장 큰 구성 요소가 무엇이고 왜 큰지 한 문단.

## 3. 작업(브랜치·worktree)별

| 작업 | 작업 공간 | 기간(KST) | 결과 | 부모 | 하위 에이전트 | 합계 | 비중 |
| --- | --- | --- | --- | ---: | ---: | ---: | ---: |

- 결과 열: commit, 변경 파일 수와 `+추가/−삭제`, 병합·정리 여부
- 표 아래 "작업별 관찰": 작업마다 비용이 크거나 작은 이유를 2~4줄. 하위 에이전트 수, 응답당 도구, 재개, 부모 시작 컨텍스트, 오류를 근거로 든다.

## 4. 하위 에이전트별 상세

### 4.1 역할별 묶음

| 역할 | 에이전트 수 | 응답 | 도구 | 응답당 도구 | 비용 환산 | 비중 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

이어서 작업 × 역할 비용 표(작업별 Planner·Generator·Publisher·Watcher·기타).

### 4.2 에이전트별 표 (비용 환산 내림차순)

| 순위 | 에이전트 | 작업 | 역할·단계 | 기간 | 응답 | 도구 | 응답당 | 최대 컨텍스트 | 캐시 신규 | 캐시 읽기 | 출력(하한) | 비용 환산 |
| --- | --- | --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

- 에이전트는 ID 앞 8자로 적는다. 역할·단계 열에 재개 횟수와 긴 대기를 함께 적는다.
- 표 위에 시각 기준(KST), 완료·중단 여부, Watcher 판정 결과를 한 줄로 적는다.

### 4.3 주요 에이전트의 작업과 토큰 구성

비용 상위 3~5개와 재개·오류가 두드러진 에이전트마다 소절을 둔다.

- **작업**: 맡은 단계와 결과물. Write·Edit 횟수와 문자 수. 재개가 있으면 시각과 재개 이유
- **읽은 것**: 세션 문서(파일별 문자 수·횟수·부분 읽기 여부), 정책·스킬 읽기 횟수, 여러 번 읽은 파일
- **구성**: 컨텍스트 증가의 도구 범주별 비중 상위 5~6개
- **특이사항**: 평균 컨텍스트가 다른 같은 역할보다 큰 이유, 전체 재기록(시각·크기·환산), 응답당 도구, 넓은 검색(`-l` 사용 비율·최대 출력), 차단·오류(사유를 확인했으면 사유)

### 4.4 시기별 응답당 도구 수

| 시기 | 작업 | 하위 에이전트 응답 | 도구 | 응답당 도구 | 모델·버전 |
| --- | --- | ---: | ---: | ---: | --- |

- 변화가 있으면 모델·host 버전·정책 번들이 같았는지 확인하고, 이전 보고서의 가설과 맞는지 적는다.
- 응답당 도구가 높았다면 줄었을 응답 수와 캐시 읽기를 계산해 비용 영향의 상한으로 적는다.

### 4.5 하위 에이전트 낭비 지점

| 지점 | 크기 | 해당 에이전트 | 원인 | 대책 |
| --- | ---: | --- | --- | --- |

검토할 지점: 재개 시 캐시 전체 재기록, 여러 단계를 한 에이전트로 이어 처리해 커진 컨텍스트, 계획·리뷰 문서 통째 재작성, 큰 문서 통째 읽기, 넓은 검색, hook 차단과 반복, 도구 스키마로 커진 시작 컨텍스트. 대책에 중앙 정책 변경이 필요하면 `(중앙 정책)`을 붙인다.

## 5. 부모 세션

### 5.1 작업별

| 작업 | 응답 | 도구 | 컨텍스트 시작 → 최대 | 캐시 신규 | 캐시 읽기 | 출력(하한) | 비용 환산 | 하위 지시 / 회신 |
| --- | ---: | ---: | --- | ---: | ---: | ---: | ---: | --- |

이어서 "사용자 입력 구간 중 비싼 것" 표(시각, 입력 요지, 응답, 컨텍스트, 비용) 상위 5~7개.

### 5.2 소견

번호 목록. 각 항목에 수치 근거를 붙인다.

1. 이전 작업의 컨텍스트를 안고 다음 작업을 시작한 비용(작업별 시작 컨텍스트 − 새 세션 첫 응답 크기) × 응답 수
2. 긴 대기 뒤 캐시 재기록(시각, 대기 시간, 크기). 같은 시각에 재개한 하위 에이전트의 재기록도 합산
3. 자동 압축의 효과(압축 직전·직후 컨텍스트)
4. 하위 회신이 부모 컨텍스트에 쌓인 양(건수, 평균, 큰 회신)
5. 부모 도구 오류: hook 차단·보호 실행기 거부·실제 실패·기타로 나누고 같은 원인의 반복을 적는다
6. 정책 runtime 코드나 큰 문서를 읽은 경우와 그 이유
7. 하위 지시문의 건수·길이와 읽을 범위·묶음 지시 포함 여부

## 7. 개선안 (다음 작업에 적용, 우선순위순)

- 항목마다 **굵은 한 문장의 행동**, 예상 절감(이 세션 기준)과 계산 근거, 적용 방법을 적는다.
- 지시만으로 되는 것과 중앙 정책 변경이 필요한 것(`(중앙 정책)`)을 구분한다.
- 마지막에 상위 개선안을 함께 적용했을 때의 절감 추정과 그 불확실성을 적는다. 원인이 확인되지 않은 항목은 추정에서 뺐다고 밝힌다.

## 8. 산출물 대비 효율

| --- | --- |

| 하위 에이전트 | 개수, 차단·중단, 재개 횟수 |

| 컨텍스트 자동 압축 | 횟수 |

## 9. 재현

실행한 명령을 그대로 적는다(스크립트 절대 경로, `--session`, `--until`, `--tasks`, `--session-directory`). 구간 파일을 바꿔 다시 집계하는 방법도 적는다.
