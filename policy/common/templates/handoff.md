# 인계 스키마

부분 기여·인계 문서는 `handoff.template.md`에 따라 다음을 기록한다.

- 보내는·받는 host/session/role, 역할 라우팅, 목표와 현재 상태, 완료·대기 작업, 결정과 제약.
- 보내는 작업의 실제 project·branch·HEAD·worktree 절대 경로·실행 디렉터리와 확인 시점. commit 내역, staged·unstaged·untracked 변경의 경로와 내용, 보존할 기존 변경.
- 인계 대상 작업 공간별 식별 이름, 수행할 작업과 역할, project·저장소, 목적지 branch·worktree 절대 경로·실행 디렉터리, 기존/생성 예정/미정, 확인한 HEAD 또는 생성 기준 branch·commit, 직접 부모, 진입 전 확인 항목.
- 역할별 사용할 작업 공간, 남은 작업의 구체적인 변경 내용과 대상 경로, 재사용 자산, 연결 계약과 근거, 선행 조건·순서, 겹치는 변경의 조율 방법, 완료 기준·검증 명령·기대 결과, 질문할 사항, 다음 인계 역할·위치·결과.
- 공유·분리 이유, 공유 공간의 순차 수정·Git 실행 순서, 분리 공간의 부모·자식 통합 순서와 형제 검토, 승인된/미승인 Git 작업, 검증 결과와 미실행 검증, 다음 조치.

작업 공간과 역할별 상세 작업은 다음 실행을 위한 계획이며 세션의 작업 범위·접근 권한을 고정하지 않는다. UI와 Logic이 순차로 연결할 때는 같은 공간을 사용할 수 있고, 실제 병렬 수정에는 별도 linked worktree를 사용한다. 미정인 목적지나 계약은 임의로 채우지 않고 질문하며, 인계받는 작업자는 최신 사용자 요청과 실제 파일·Git 상태를 확인한다.
